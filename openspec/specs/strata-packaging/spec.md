# strata-packaging Specification

## Purpose

Определяет наблюдаемое поведение пакета `app-ai/strata` в оверлее `babylon_5`: как пакет собирается при разных USE-флагах, что он устанавливает в систему и что работает после установки без исходного дерева Strata.

## Requirements

### Requirement: Пакет доступен из оверлея
Оверлей `babylon_5` SHALL предоставлять пакет `app-ai/strata` версии 0.2.20 (исходный тег `v0.2.20`) с корректным Manifest, лицензией MIT и KEYWORDS `~amd64`, собираемый из исходников GitHub без бинарных поставок.

#### Scenario: Установка из оверлея
- **WHEN** пользователь с подключённым оверлеем `babylon_5` выполняет `emerge app-ai/strata`
- **THEN** Portage находит пакет `app-ai/strata-0.2.20`, скачивает исходный архив по SRC_URI и установка завершается без ошибок

### Requirement: Сборка движка выбирается GPU USE-флагами
Пакет SHALL собирать C++ движок `strata` только когда включён `cuda` или `hip`, с зависимостями от соответствующего тулкита; одновременное включение обоих флагов MUST блокироваться через REQUIRED_USE, поскольку система сборки upstream запрещает оба бэкенда сразу.

#### Scenario: NVIDIA-сборка
- **WHEN** пакет устанавливается с `USE=cuda`
- **THEN** движок компилируется с CUDA-бэкендом и исполняемый файл движка устанавливается в систему

#### Scenario: AMD-сборка
- **WHEN** пакет устанавливается с `USE=hip`
- **THEN** движок компилируется с HIP/ROCm-бэкендом и исполняемый файл движка устанавливается в систему

#### Scenario: Конфликт бэкендов
- **WHEN** пользователь пытается установить пакет с `USE="cuda hip"`
- **THEN** Portage отклоняет установку с предупреждением REQUIRED_USE, не начиная сборку

### Requirement: Установка без GPU-флагов сохраняет рабочий CLI и сервер
При выключенных `cuda` и `hip` пакет SHALL успешно собираться без CUDA/ROCm тулкитов и устанавливать CLI `strata` и Python-сервер с веб-интерфейсом; сам движок при этом в комплект не входит и может быть получен штатным механизмом Strata во время работы.

#### Scenario: Установка на машину без GPU-тулкитов
- **WHEN** пакет устанавливается без USE-флагов `cuda` и `hip`
- **THEN** сборка проходит без запроса CUDA/ROCm, а `strata --help` завершается успешно

### Requirement: CLI и сервер работают на системном Python без исходного дерева
Команда `strata` SHALL запускаться на системном Python 3.10+, все runtime-Python-зависимости (numpy, jinja2, regex, pyyaml, tqdm, requests, pillow, psutil) SHALL быть объявлены как зависимости ebuild; пакет не должен полагаться на pip, venv или наличие checkout Strata.

#### Scenario: Первый запуск на чистой системе
- **WHEN** сразу после установки, без каталога с исходниками Strata, выполняется `strata --help`
- **THEN** CLI печатает справку и завершается кодом 0, не обращаясь к сети

### Requirement: Сервер предоставляет веб-интерфейс и API на localhost
Установленный пакет SHALL содержать серверную часть с веб-интерфейсом (статические ассеты включительно) и OpenAI/Anthropic-совместимым HTTP API, доступными на localhost после запуска сервера штатной командой Strata.

#### Scenario: Проверка состава пакета
- **WHEN** после установки проверить содержимое пакета (`qlist app-ai/strata`)
- **THEN** в нём присутствуют модули сервера и ассеты веб-интерфейса по путям, зарегистрированным в ebuild

### Requirement: Опциональный кодировщик изображений
Флаг `vision` SHALL добавлять сборку и установку кодировщика изображений (`strata-vision` для CUDA, `strata-vision-hip` для HIP), расширяющего веб-интерфейс вводом картинок; по умолчанию флаг выключен и кодировщик не устанавливается. Описание флага в `metadata.xml` и `use.local.desc` MUST соответствовать фактическим зависимостям (зависит от выбранного GPU-бэкенда; OpenCL не используется). Сборка кодировщика SHALL использовать распараллеливание в соответствии с `MAKEOPTS`.

#### Scenario: Установка с vision
- **WHEN** пакет установлен с `USE=vision`
- **THEN** исполняемый файл `strata-vision` входит в состав пакета

#### Scenario: Установка по умолчанию
- **WHEN** пакет установлен без флага `vision`
- **THEN** `strata-vision` в состав пакета не входит

#### Scenario: Точное описание флага
- **WHEN** пользователь смотрит описание `vision` (`equery uses`, `euse`)
- **THEN** текст описывает кодировщик для CUDA/HIP-бэкенда и не упоминает OpenCL

#### Scenario: Сборка с учётом MAKEOPTS
- **WHEN** пакет собирается с `USE=vision` и `MAKEOPTS="-j16"`
- **THEN** компиляция единиц кодировщика выполняется параллельно (до ~16 задач), а не последовательно

### Requirement: Сборка не требует сети и не поставляет модели
Сборка пакета SHALL проходить в сетевой песочнице Portage (все исходники, включая ggml, вендорены в архиве релиза; тестовый корпус не собирается), и пакет MUST NOT включать файлы моделей.

#### Scenario: Сборка в песочнице
- **WHEN** сборка выполняется с отключённой сетью (FEATURES network-sandbox)
- **THEN** configure и compile завершаются успешно

#### Scenario: Отсутствие моделей
- **WHEN** проверить содержимое установленного пакета
- **THEN** в нём нет файлов моделей (GGUF, expert packs) и загрузчиков моделей

### Requirement: Системный сервис сервера
Пакет SHALL устанавливать системного пользователя `strata` (домой `/var/lib/strata`), systemd-юнит `strata.service`, запускающий `strata serve` под этим пользователем, конфиг адреса/порта `/etc/strata/daemon.conf` и конфигурацию сервера `/etc/strata/strata.json`; адрес прослушивания по умолчанию — только localhost.

#### Scenario: Состав после установки
- **WHEN** после `emerge app-ai/strata` проверить систему
- **THEN** существуют пользователь/группа `strata`, юнит `strata.service` (включённый в multi-user.target), `/etc/strata/daemon.conf` и `/etc/strata/strata.json`

#### Scenario: Настройка хоста и порта
- **WHEN** изменить `STRATA_HOST`/`STRATA_PORT` в `/etc/strata/daemon.conf` и выполнить `systemctl restart strata`
- **THEN** сервер слушает указанные адрес и порт (юнит читает их через `EnvironmentFile`)

#### Scenario: Изоляция от пользовательских установок
- **WHEN** сервис запущен
- **THEN** все его данные лежат в `/var/lib/strata`, и он не читает и не изменяет каталоги пользователей (`~/.local/share/strata` и т.п.)

#### Scenario: Движок доступен сервису
- **WHEN** пакет собран с `USE=cuda` (или `hip`) и сервис запускается впервые
- **THEN** системный компонент движка из `/usr/lib/strata/engine` зарегистрирован для пользователя `strata` и используется `serve`

### Requirement: Биндлинг GPU-рантаймов лицензионно отражён
Пакет, устанавливающий двоичные рантайм-библиотеки CUDA/ROCm, SHALL объявлять соответствующие им лицензии в `LICENSE` (с учётом USE-флагов) и включать их тексты в каталог лицензий установленного пакета; `LICENSE="MIT"` одна MUST NOT описывать комплект с проприетарными бинарниками.

#### Scenario: Состав лицензий
- **WHEN** проверить метаданные установленного пакета, собранного с `USE=cuda`
- **THEN** в лицензии пакета присутствуют NVIDIA-лицензии на поставляемые рантайм-библиотеки, их тексты установлены в каталог лицензий

#### Scenario: HIP-сборка
- **WHEN** пакет собран с `USE=hip`
- **THEN** аналогично отражены лицензии ROCm-компонентов

### Requirement: Предстартовая регистрация движка выполняется устанавливаемым скриптом
Шаг предстартовой регистрации движка в `strata.service` SHALL вызывать исполняемый файл, входящий в состав пакета; юнит и ebuild MUST NOT содержать инлайнового shell-кода этого шага и подстановок shell-выражений в шаблон юнита. Скрипт обязан быть идемпотентным, а его сбой — различим в журнале systemd и не срывать запуск сервера.

#### Scenario: Юнит не содержит shell-логики
- **WHEN** открыть установленный `strata.service`
- **THEN** `ExecStartPre` указывает на абсолютный путь исполняемого файла пакета, без `/bin/sh -c`, составных условий и префикса подавления ошибок

#### Scenario: Идемпотентность
- **WHEN** сервис перезапускается повторно после успешной регистрации
- **THEN** регистрация не выполняется заново, запуск завершается успешно

#### Scenario: Сборка без GPU-флагов
- **WHEN** сервис запускается на установке, собранной без `USE=cuda|hip`
- **THEN** шаг регистрации завершается успешно без сообщений, сервер работает

#### Scenario: Сбой остаётся видимым
- **WHEN** регистрация движка не удается (например, каталог данных недоступен на запись)
- **THEN** в журнале systemd присутствует сообщение скрипта с кодом возврата, сервер запущен

### Requirement: Зависимости monitor-режима доступны из оверлея
Пакеты `dev-python/textual` и его runtime-зависимости, требуемые ebuild при `USE=monitor`, SHALL быть установлены из связки оверлеев `babylon_5` + `::gentoo` на версиях, удовлетворяющих RDEPEND ebuild; установка `app-ai/strata` с флагами по умолчанию MUST разрешаться без подключения сторонних репозиториев (guru и т.п.).

#### Scenario: Установка с флагами по умолчанию
- **WHEN** на системе с подключёнными только `::gentoo` и `babylon_5` выполняется `emerge app-ai/strata` без изменения USE
- **THEN** расчёт зависимостей завершается успешно, сборка проходит, пакет устанавливается

#### Scenario: Монитор на консоли
- **WHEN** сразу после установки выполнить `strata monitor` в текстовой консоли (без X/Wayland)
- **THEN** TUI-экран монитора отображается и сессия корректно завершается по выходу из монитора

### Requirement: Владение устанавливаемых файлов гарантировано зависимостью
Все группы и пользователи, передаваемые в `fowners`/`fperms` фазами установки, SHALL быть объявлены в `DEPEND` ebuild; для `root:strata` это означает наличие `acct-group/strata` в `DEPEND`.

#### Scenario: Владельцы после merge
- **WHEN** после установки проверить права файлов `/etc/strata/*` и `/var/lib/strata`
- **THEN** владельцем указанных файлов значится `root:strata`, группа `strata` существует на момент merge

#### Scenario: Порядок установки
- **WHEN** `app-ai/strata` merge-ится на системе, где `acct-group/strata` ещё не установлен
- **THEN** Portage устанавливает `acct-group/strata` до merge пакета strata, `fowners` не вызывает ошибку несуществующей группы

### Requirement: Зависимости фазы сборки наследуются от eclass
Ebuild `app-ai/strata` MUST НЕ перекрывать управляемые eclass переменные зависимостей собственными списками, ссылающимися на несуществующие пакеты; инструменты сборки C++ (cmake, ninja) SHALL попадать в зависимости через `cmake.eclass`.

#### Scenario: Нет ссылок на несуществующие категории
- **WHEN** проверить полный список зависимостей ebuild (расчёт merge)
- **THEN** ни одна зависимость не указывает на несуществующую категорию/пакет (в частности, отсутствует `dev-build/ninja`)

#### Scenario: Сборка после исправления
- **WHEN** пакет пересобирается с `USE=cuda` после удаления строки BDEPEND
- **THEN** configure и compile проходят успешно, ninja берётся из `dev-util/ninja`

### Requirement: Требование к версии NVIDIA-драйвера явно и документировано
Минимальная версия NVIDIA-драйвера, проверяемая при регистрации движка, SHALL задаваться одной именованной переменной ebuild и быть описана в README пакета (происхождение значения, способ переопределения, последствия понижения).

#### Scenario: Единственное место определения
- **WHEN** изучить ebuild на предмет версий драйвера
- **THEN** литерал версии встречается однократно в именованной переменной, а не в тексте команды

#### Scenario: Регистрация на поддерживаемом драйвере
- **WHEN** регистрация движка выполняется на системе с драйвером не ниже порога
- **THEN** регистрация проходит успешно

### Requirement: Артефакты компонентов самодостаточны по библиотекам
Исполняемые файлы и общие библиотеки установленных компонентов (`/usr/lib/strata/...`) SHALL разрешать свои копируемые зависимости без `LD_LIBRARY_PATH` и системного LDCONFIG-каталога тулкита; запуск штатными командами (CLI, systemd-сервис) MUST завершаться успешно на системе без переменных окружения тулкита.

#### Scenario: Запуск без окружения
- **WHEN** выполнить запуск движка/сервера из чистого окружения (`env -i`, без `LD_LIBRARY_PATH`)
- **THEN** процесс стартует, ошибка вида `error while loading shared libraries: libnvrtc/librocblas...` не появляется

#### Scenario: Аудит dynamic-секций
- **WHEN** для всех ELF-артефактов компонентов проверить `objdump -p`/`ldd`
- **THEN** каждая NEEDED-зависимость разрешена (через runpath с `$ORIGIN` или системный путь), «not found» отсутствует
