# Spec Delta

## Purpose

Определяет поведение средств администрирования моделей Strata на хосте: просмотр каталога доступных моделей, скачивание модели с созданием полного окружения изолированного инстанса, обзор и диагностику установленных моделей, их удаление.

## ADDED Requirements

### Requirement: Каталог доступных моделей доступен из командной строки
Скрипт `strata-list-available` SHALL печатать families и модели из каталога, поставляемого с пакетом (`/usr/share/strata/setup.py`), по одному на строку с идентификатором и кратким описанием; непустой аргумент family SHALL фильтровать вывод по family.

#### Scenario: Полный список
- **WHEN** администратор выполняет `strata-list-available`
- **THEN** вывод содержит не менее одной модели вида `<family>/<model>` с описанием и завершается кодом 0

#### Scenario: Фильтр по family
- **WHEN** выполняется `strata-list-available <family>` для несуществующего family
- **THEN** скрипт завершается с ненулевым кодом и понятным сообщением об отсутствии такого family

### Requirement: Скачивание модели создаёт полное окружение инстанса
`strata-download-model <family>/<model>` SHALL создать изолированную install-папку `/var/lib/strata/<model>` и каталог данных в ней, скачать модель от имени пользователя `strata`, сгенерировать ран-конфиг, указывающий на общий компонент движка, и написать `/etc/strata/<model>/daemon.conf` с адресом `127.0.0.1` и портом `8080`.

#### Scenario: Новая модель
- **WHEN** администратор выполняет `strata-download-model <family>/<model>` для отсутствующей модели
- **THEN** после завершения существуют `/var/lib/strata/<model>/strata-<model>.json` (движок — компонент, порт 8080) и каталог данных, владелец всего — `strata`, а `/etc/strata/<model>/daemon.conf` содержит `STRATA_HOST=127.0.0.1` и `STRATA_PORT=8080`

#### Scenario: Запуск сразу после скачивания
- **WHEN** после успешного `strata-download-model` выполнить `systemctl start strata@<model>`
- **THEN** сервер запускается и слушает `127.0.0.1:8080` без ручного редактирования конфигов

#### Scenario: Недопустимая пара отклоняется до скачивания
- **WHEN** аргументы не соответствуют ни одной паре `<family>/<model>` каталога
- **THEN** скрипт завершается с ненулевым кодом до начала скачивания и не создаёт каталогов инстанса

#### Scenario: Повтор для незавершённой модели
- **WHEN** скрипт повторно вызван для того же `<family>/<model>`, скачивание которого ранее прервалось
- **THEN** скачивание продолжается с сохранением загруженных файлов и завершает создание окружения

### Requirement: Инстансы моделей изолированы
Каждый инстанс SHALL существовать отдельно: ран-конфиг, логи и данные модели лежат в `/var/lib/strata/<id>`, сервер и диагностические команды инстанса MUST видеть только его модель; каталог компонентов с владельцем `strata` (общий движок) SHALL быть общим — файлы движка MUST NOT дублироваться на каждый инстанс.

#### Scenario: Две модели одновременно
- **WHEN** скачаны две модели и запущены `strata@<a>` и `strata@<b>`
- **THEN** каждый сервер работает только со своей моделью, и обе работают одновременно

#### Scenario: Движок не дублируется
- **WHEN** проверить содержимое `/var/lib/strata` после установки двух моделей
- **THEN** каталог компонентов содержит одну копию системного движка, используемую обоими инстансами

### Requirement: Обзор установленных моделей
`strata-list-installed` SHALL перечислять созданные инстансы по одному на строку с идентификатором модели, портом, занятых моделью диском объёмом и состоянием её сервиса.

#### Scenario: Список после скачивания
- **WHEN** выполнены `strata-download-model` для одной модели и `strata-list-installed`
- **THEN** вывод содержит строку с id этой модели, портом 8080, ненулевым размером и состоянием сервиса, завершаясь кодом 0

#### Scenario: Нет инстансов
- **WHEN** `strata-list-installed` выполняется на системе без скачанных моделей
- **THEN** вывод объясняет отсутствие инстансов и завершается кодом 0

### Requirement: Диагностика одной модели
`strata-models-inspect <id>` SHALL печатать только для указанной модели размещение и состояние её инстанса: путь ран-конфига и каталога весов с размером на диске, путь env-файла с портом, каталожные данные модели (пара, размеры, лицензия) и состояние сервиса; неизвестный id или несохранённый инстанс MUST приводить к ненулевому коду и понятному сообщению.

#### Scenario: Известная модель
- **WHEN** выполнить `strata-models-inspect <id>` для скачанной модели
- **THEN** вывод содержит поля её ран-конфига и не содержит сведений о других установленных моделях

#### Scenario: Неизвестный id
- **WHEN** выполнить `strata-models-inspect nonexistent`
- **THEN** скрипт завершается с ненулевым кодом и сообщением об отсутствии такого инстанса

### Requirement: Удаление модели затрагивает только её инстанс
`strata-rm-model <id>` SHALL удалить инстанс целиком (`/var/lib/strata/<id>` и `/etc/strata/<id>`) и MUST отказаться удалять запущенный инстанс, указав команду остановки; пути вне этих двух поддеревьев MUST NOT удаляться, другие инстансы и общий каталог компонентов MUST оставаться нетронутыми.

#### Scenario: Запущенный инстанс не удаляется
- **WHEN** `strata-rm-model <id>` вызван для активного `strata@<id>`
- **THEN** скрипт завершается с ненулевым кодом, файлы инстанса сохранены, вывод содержит `systemctl stop strata@<id>`

#### Scenario: Успешное удаление
- **WHEN** выполнить `strata-rm-model <id>` для остановленного инстанса
- **THEN** `/var/lib/strata/<id>` и `/etc/strata/<id>` отсутствуют, данные остальных инстансов и каталог компонентов не изменены

### Requirement: Справка доступна для всех скриптов управления моделями
Каждый из скриптов `strata-list-available`, `strata-download-model`, `strata-list-installed`, `strata-models-inspect`, `strata-rm-model` SHALL по `--help` (и `-h`) печатать без прав root подробную справку: назначение, синтаксис, аргументы, создаваемые/удаляемые пути и примеры, завершаясь кодом 0.

#### Scenario: Справка без прав администратора
- **WHEN** обычный пользователь выполняет `<скрипт> --help` для любого из пяти скриптов
- **THEN** напечатана справка с примерами, код возврата 0
