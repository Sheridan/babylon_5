# Design

## Context

Юнит пишет stdout в журнал; `strata.json` с ключом `log` дублирует логирование в файл `/var/lib/strata/strata.log`. README запрещает `log` в json (позиция «источник истины — journal»). Про preservation: `/etc` входит в `CONFIG_PROTECT` по умолчанию (make.globals), поэтому изменённые пользователем файлы при апгрейде сохраняются, а новый вариант кладётся в `._cfg0000_strata.json` — нужно это задокументировать, а не чинить ebuild.

## Goals / Non-Goals

**Goals:** один непротиворечивый рассказ: где логи, где конфиг, что происходит при апгрейде.
**Non-Goals:** не менять формат daemon.conf; не трогать REPLACE-плейсхолдеры strata.json.

## Decisions

- Логи: оставить `"log"` в strata.json (файл нужен для отладки упавшего сервиса) и переписать README в соответствии с фактом; альтернатива (убрать log из json) лишена полезного канала, если журнал уже собран в journald — но файл читают и вне systemd. Выбирается вариант «json с log + README о обоих каналах» — проверяется задачей «сервер пишет strata.log».
- Абзац harness.log — удалить (артефакт старого тула).

## Risks / Trade-offs

- Ротация strata.log не настроена — зафиксировать в README как ответственность администратора.
