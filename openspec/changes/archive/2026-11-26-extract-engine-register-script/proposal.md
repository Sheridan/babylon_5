# Why

Предстартовая регистрация движка реализована однострочной shell-командой, «впаянной» в тело ebuild (строки 314–331): строка с одинарными кавычками и вложенными вызовами подставляется в шаблон `strata.service` через `sed`, для чего вручную экранируется `|` и `&` (строки 326–328). Получилась трёхслойная кавычка (ebuild → sed → systemd → `/bin/sh -c`): её нельзя ни проверить статически, ни прочитать в установленном юнитe, любая правка ломается об экранирование. Каталог компонента (`engine/<версия>`) «запекается» в юнит при сборке, хотя trivialно находится в рантайме.

## What Changes

- В пакет устанавливается хелпер-скрипт `/usr/lib/strata/engine-register` (файл в `files/`, установка через `dobin`): идемпотентная регистрация движка по stamp-файлу, каталог компонента находится в рантайме, при сбое — сообщение с кодом возврата в stderr (журнал systemd), код возврата скрипта при этом нулевой, чтобы запуск сервера не срывался.
- `files/strata.service` становится статическим файлом: `ExecStartPre=/usr/lib/strata/engine-register` вместо плейсхолдера `@ENGINE_PRE@`.
- Из `src_install` удаляются построение `engine_pre`, `sed`-подстановка и экранирование (строки 314–331); `systemd_dounit` получает `FILESDIR`-файл напрямую.
- Обёртка `/usr/bin/strata` и heredocs `BUILD.json` оставаются в ebuild: они подставляют build-time-значения (`${PYTHON}`, версии тулкитов) и переносимы только с потерей читаемости (критерий: рантайм-логика — в `files/`, build-time-подстановка — в ebuild).

### Modified Capabilities

- `strata-packaging`: новое требование — предстартовый шаг юнита вызывает устанавливаемый скрипт, юнит не содержит инлайнового shell-кода.

## Impact

- Новый файл `app-ai/strata/files/strata-engine-register`; правки `files/strata.service` и `app-ai/strata/strata-0.2.20.ebuild` (`src_install`).
- Пересекается с `visible-engine-reg-pre` (тот же шаг, требование «сбой виден в журнале»): порядок применения любой — после обоих change-ей юнит приходит к одному виду (скрипт без `-`-префикса); рекомендуется применять `visible-engine-reg-pre` первым, затем это изменение как рефакторинг формы.
- Установленные системы: содержимое юнита меняется (перечитывается `daemon-reload`-ом в `pkg_postinst`), поведение пре-старта эквивалентно.
