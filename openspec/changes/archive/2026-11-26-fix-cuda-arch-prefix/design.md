# Design

## Context

`cuda-arch.eclass`/`cuda_get_arch_flags` оперируют значениями вида `sm_120`/`compute_120`. Ebuild дважды навешивает префикс `sm_`. В текущей сборке критический путь идёт через `-DCMAKE_CUDA_ARCHITECTURES=${cuda_cmake}`, поэтому артефакт собран корректно; ошибка скрыта для основного gencode, но реальна для аргумента `--arch`.

## Goals / Non-Goals

**Goals:** один источник истины для записи архитектуры; отсутствие `sm_sm_`.
**Non-Goals:** не менять набор поддерживаемых архитектур.

## Decisions

- Убрать ручной префикс: `--arch "${a}"`. Перед правкой уточнить потребитель аргумента (`setup.py`/скрипт upstream) — если потребитель ждёт именно `sm_NNN`, нормализовать: `${a#sm_}` + `sm_`.

## Risks / Trade-offs

- Проверка обязательна: сравнить `nvcc`-команды/логи до и после (флаг `--log-verbose` сборки движка), чтобы не сломать рабочий основной путь.
