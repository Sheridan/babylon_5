# Why

В `src_configure` (строка ~245) архитектура передаётся как `--arch "sm_${a}"`, где `${a}` берётся из списка архитектур CUDA и уже содержит префикс (`sm_120`, `compute_120`). На выходе получается `sm_sm_120` — некорректное значение для nvcc/gencode. Основной путь сборки спасается тем, что реальные флаги кодогенерации задаются через `CMAKE_CUDA_ARCHITECTURES`, но любой потребитель `--arch` получает битый аргумент.

## What Changes

- Исправить формирование аргумента: использовать значение архитектуры как есть (или нормализовать префикс), чтобы в командную строку попадало `sm_<arch>`.

## Итог (2026-11-26): изменение закрыто без правок (no-op)

Проверка исходников v0.2.20 (`tools/packaging/package_engine.py`) показала,
что аргумент `--arch` принимает формат `sm_NN` (префикс `sm_` снимается самим
скриптом, значения нормализуются к спискам CMake `CUDA_ARCHITECTURES`).
Формулировка отчёта ревью об «ошибочном префиксе» несостоятельна:
`--arch "sm_${a}"` в эбилде корректен, изменений не требуется.
