# Design

## Context

`app-ai/strata/strata-0.2.20.ebuild` (строка 39): `monitor? ( dev-python/textual[anyio(-)?,typing-extensions(-)?] )`; `IUSE_DEFAULTS="monitor"` (строка 15). В снапшоте `::gentoo` на системе пакетов `textual`, `linkify-it-py`, `uc-micro-py` нет вовсе; `mdit-py-plugins` 0.3.0, `rich` 11.2/12.0 — ниже требований textual 8.2.8 (`rich>=14.2.0`, `pygments>=2.19.2,<3`, `platformdirs>=3.6,<5`, `markdown-it-py[linkify]>=2.1.0`, `mdit-py-plugins`, `typing-extensions>=4.4,<5`). Система пользователя уже содержит textual 8.2.8 и совместимые версии closure (установлены из guru до его отключения) — это подтверждённый рабочий набор версий.

## Goals / Non-Goals

**Goals:**
- `emerge app-ai/strata` с USE-флагами по умолчанию разрешается и ставится из связки babylon_5 + ::gentoo без guru.
- `strata monitor` работает на консоли после установки.

**Non-Goals:**
- Не переводим `monitor` в разряд выключенных по умолчанию флагов.
- Не трогаем остальные зависимости ebuild.

## Decisions

- **Вендорим, а не выключаем флаг по умолчанию.** Решение пользователя: monitor должен работать из коробки (см. также требование «Системный сервис сервера» — monitor часть продукта).
- **Версии — проверенный набор системы** (textual 8.2.8 и компании), ebuildы из PyPI-sdist на `distutils-r1`; где существует ebuild в guru — переносим его как базу (лицензии, зависимости).
- **Bump общих зависимостей только в пределах, требуемых textual**, с проверкой, что установленные пакеты систем не ломаются (проверка обратных зависимостей `equery h`/glso-check на тестовой системе).
- Альтернатива — RDEPEND без версионных диапазонов/набор USE `(-)` — отклонена: версии задаёт textual, а не strata.

## Risks / Trade-offs

- Дублирование python-пакетов в оверлее размывает ::gentoo: примем как плату за автономность; при появлении textual в ::gentoo изменения архивируются.
- Конфликт версий с будущими пакетами оверлея — низкий, closure маленькая.
